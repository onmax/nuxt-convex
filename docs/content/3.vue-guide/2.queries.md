Use `useConvexQuery` when you want one reactive query subscription in a Vue or Nuxt component.

## Subscribe to a query

```vue [src/components/TaskList.vue]
<script setup lang="ts">
import { useConvexQuery } from 'vue-convex'
import { api } from '../convex/_generated/api'

const { data, error, status } = useConvexQuery(
  api.tasks.list,
  { userId: 'user_123' },
)
</script>
```

`status` is `pending` until the first result arrives, then `success` or `error`, and `idle` while the query is skipped.

## Wait for the first result

The return value is awaitable. Inside an async `setup()` (under `<Suspense>`, which Nuxt provides), `await` waits for the first result or error and never rejects:

```ts
const { data, error } = await useConvexQuery(api.tasks.list, { userId: 'user_123' })
```

During SSR this is what makes the query run on the server. The result is then hydrated, so the client renders the same HTML and continues over the WebSocket. See [Realtime and SSR](/convex-patterns/realtime-and-ssr).

## Handle errors

`error` holds a `ConvexError` when your function throws one. `isConvexError(error, code?)` checks it and matches `data` or `data.code`:

```ts
import { isConvexError } from 'vue-convex'

if (isConvexError(error.value, 'NOT_FOUND'))
  showNotFound()
```

## Use reactive arguments

Pass a `ref`, `computed`, or getter when the query arguments can change over time.

```vue [src/components/UserTasks.vue]
<script setup lang="ts">
import { useConvexQuery } from 'vue-convex'
import { api } from '../convex/_generated/api'

const props = defineProps<{ userId: string }>()

const { data } = useConvexQuery(
  api.tasks.list,
  computed(() => ({ userId: props.userId })),
)
</script>
```

When the arguments change, the new subscription starts and the old one is cleaned up. `data` resets to `undefined` until the new result arrives; pass `{ keepPreviousData: true }` to keep showing the old result instead. Arguments that are deep-equal don't resubscribe.

## Skip a query until you have the inputs

Pass `"skip"` when the query should stay inactive until another piece of state is ready.

```vue [src/components/UserProfile.vue]
<script setup lang="ts">
import { useConvexQuery } from 'vue-convex'
import { api } from '../convex/_generated/api'

const props = defineProps<{ userId?: string }>()

const { data, isSkipped } = useConvexQuery(
  api.users.get,
  computed(() => props.userId ? { userId: props.userId } : 'skip'),
)
</script>
```

## Wait for authentication

Use `auth: 'required'` for queries that only make sense for a signed-in user. The query stays idle until the user is authenticated:

```ts
const { data } = useConvexQuery(api.tasks.myTasks, {}, { auth: 'required' })
```

## Disable SSR for a query

Use `{ server: false }` when a query should only run in the browser, for example when SSR has no access to the user's auth.

```ts
const { data } = useConvexQuery(api.tasks.myTasks, {}, { server: false })
```

## Verify the result

The query setup is working when:

- `await useConvexQuery(...)` resolves with `status` `success`
- `data` updates after the first response
- changing the reactive arguments updates the subscription
