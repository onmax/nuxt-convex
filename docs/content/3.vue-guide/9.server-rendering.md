Most Vue apps that use `vue-convex` are client-rendered, and this page doesn't concern them: queries start `pending` and fill in over the WebSocket. If you use Nuxt, the module does everything below for you; read [SSR & Hydration](/nuxt-module/ssr-and-hydration) instead.

This page is for apps that render on the server themselves, with `createSSRApp` and `renderToString` (a custom Vite SSR setup, for example).

## What runs where

| | Server | Browser |
| --- | --- | --- |
| Awaited `useConvexQuery` and `useConvexPaginatedQuery` | Fetched once over HTTP | Hydrated, then live over the WebSocket |
| Queries you don't await | Rendered as `pending` | Loaded over the WebSocket |
| `useConvexQueries` | Every entry `undefined` | Loaded over the WebSocket |
| Mutations, actions, uploads | Reject: no realtime client | Run over the WebSocket |
| `useConvexAuth({ fetchToken })` | Ignored | Authenticates the client |

Awaiting requires an async `setup()` inside `<Suspense>`, which `renderToString` waits for.

## Hand results to the client

The plugin's `hydration` option is the bridge. On the server it receives every settled query; on the client it gives them back while the app hydrates:

```ts [src/entry-server.ts]
import type { ConvexHydrationEntry } from 'vue-convex'
import { convexVue } from 'vue-convex'
import { createSSRApp } from 'vue'
import { renderToString } from 'vue/server-renderer'
import App from './App.vue'

export async function render(url: string) {
  const entries: Record<string, ConvexHydrationEntry> = {}
  const app = createSSRApp(App).use(convexVue, {
    url: process.env.CONVEX_URL,
    hydration: {
      set: (key, entry) => { entries[key] = entry },
      get: () => undefined,
      isHydrating: () => false,
    },
  })

  const html = await renderToString(app)
  // Serialize safely: entries contain user data
  const state = JSON.stringify(entries).replace(/</g, '\\u003c')
  return `${html}<script>window.__CONVEX__=${state}</script>`
}
```

```ts [src/entry-client.ts]
import type { ConvexHydrationEntry } from 'vue-convex'
import { convexVue } from 'vue-convex'
import { createSSRApp } from 'vue'
import App from './App.vue'

const entries = (window as { __CONVEX__?: Record<string, ConvexHydrationEntry> }).__CONVEX__ ?? {}
let hydrating = true

createSSRApp(App, { onHydrated: () => (hydrating = false) })
  .use(convexVue, {
    url: import.meta.env.VITE_CONVEX_URL,
    hydration: {
      set: () => {},
      get: key => entries[key],
      isHydrating: () => hydrating,
    },
  })
  .mount('#app')
```

```vue [src/App.vue]
<script setup lang="ts">
defineProps<{ onHydrated?: () => void }>()
</script>

<template>
  <Suspense @resolve="onHydrated?.()">
    <RouterView />
  </Suspense>
</template>
```

Stop hydrating once the root `<Suspense>` resolves, not right after `mount()`: components below an async `setup()` are created later, and they need their entries too. After that, queries never read stale server results.

Entries are plain JSON. `bigint`, `ArrayBuffer` and `ConvexError` data survive the round trip.

## Render as the signed-in user

Pass `serverAuth` on the server to run awaited queries with the request's token. `getToken` is called at most once per app instance, and the token is never serialized:

```ts
createSSRApp(App).use(convexVue, {
  url: process.env.CONVEX_URL,
  serverAuth: { getToken: () => getConvexTokenFromRequest(request) },
  initialAuth: { isAuthenticated: Boolean(session) },
  hydration,
})
```

Pass the same `initialAuth` to the client plugin (serialize the boolean, never the token), so the auth components render the same slot on both sides. Queries marked `auth: 'none'` skip `getToken` and run anonymously.

Remember that responses rendered with a token contain that user's data: send them with `Cache-Control: private` and keep them out of shared caches.
