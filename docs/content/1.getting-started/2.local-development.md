Local development runs two processes: `npx convex dev`, which pushes your functions and generates types on every save, and `nuxt dev`.

## Run both processes

```bash [Terminal 1]
npx convex dev
```

```bash [Terminal 2]
npx nuxt dev
```

The first run of `npx convex dev` asks you to log in and pick or create a project. It then:

- creates a development deployment for you
- writes `CONVEX_DEPLOYMENT` and `CONVEX_URL` (plus `CONVEX_SITE_URL`) to `.env.local`
- generates `convex/_generated/`, which `#convex/api` points at
- watches `convex/` and pushes every change

Start them in any order. If `nuxt dev` starts first, the module notices when `convex/_generated/` appears and picks it up without a restart.

To run both from one terminal, let the Convex CLI start Nuxt alongside it:

```bash [Terminal]
npx convex dev --start 'nuxt dev'
```

## Environment variables

Nuxt loads `.env` by itself but not `.env.local`, which is where `npx convex dev` writes. `nuxt-convex` reads `.env.local` itself, in development only.

The deployment URL is resolved in this order, first match wins:

| # | Source | When |
| --- | --- | --- |
| 1 | `convex.url` in `nuxt.config.ts` | always |
| 2 | `CONVEX_URL` | process env, or `.env` |
| 3 | `NUXT_PUBLIC_CONVEX_URL` | process env, or `.env` |
| 4 | `VITE_CONVEX_URL` | process env, or `.env` (the Convex CLI writes this name when your `package.json` lists `vite`) |
| 5 | the same names in `.env.local` | `nuxt dev` only |

The site URL, used by the Better Auth proxy, follows the same order with `convex.siteUrl`, `CONVEX_SITE_URL`, `NUXT_PUBLIC_CONVEX_SITE_URL` and `VITE_CONVEX_SITE_URL`. When none is set, it's derived from the deployment URL: `https://x.convex.cloud` becomes `https://x.convex.site`, and a local backend's port goes up by one.

At run time, `NUXT_PUBLIC_CONVEX_URL` and `NUXT_PUBLIC_CONVEX_SITE_URL` override whatever was resolved at build time. See [Deployment](/nuxt-module/deployment).

`CONVEX_DEPLOYMENT` isn't needed by the app. The module uses it to link the DevTools tab to the right deployment in the Convex dashboard.

::note
`.env.local` is only read by `nuxt dev`. `nuxt build` and `nuxt generate` ignore it, so a production build never picks up a developer's deployment by accident. Pass `--dotenv .env.local` to `nuxi build` if you do want it.
::

## Work without a Convex account

Convex can run a local, anonymous backend, with no login. It's handy for trying the module, for CI, and for coding agents:

```bash [Terminal]
CONVEX_AGENT_MODE=anonymous npx convex dev
```

The backend listens on `http://127.0.0.1:3210`, HTTP actions on port `3211`, and the dashboard on `http://127.0.0.1:6790`. The CLI writes those URLs to `.env.local` as usual, the site URL is derived correctly, and the DevTools tab links to the local dashboard. Data lives on your machine; run `npx convex dev` again without the variable to move to a cloud deployment later.

## Set Convex environment variables

Variables your Convex functions read, such as `BETTER_AUTH_SECRET` or R2 credentials, live in the deployment, not in Nuxt's `.env`:

```bash [Terminal]
npx convex env set BETTER_AUTH_SECRET "$(openssl rand -base64 32)"
npx convex env list
```

## DevTools

With Nuxt DevTools enabled, the module adds a **Convex** tab in development. It links to your deployment's data, functions and logs in the Convex dashboard (the dashboard refuses to be embedded, so it opens in a new tab). Turn it off with `convex.devtools: false`.
