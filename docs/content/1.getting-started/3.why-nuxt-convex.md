Convex ships an official React client. For Vue and Nuxt, you either use the framework-agnostic `convex/browser` client yourself or pick a community integration. This page lays out what each option gives you, so you can choose.

## Using `convex/browser` directly

`convex/browser` exports `ConvexClient` (WebSocket subscriptions, mutations, actions, auth) and `ConvexHttpClient` (one-off HTTP calls). They work in any Vue app:

```ts
import { ConvexClient } from 'convex/browser'
import { onScopeDispose, shallowRef } from 'vue'
import { api } from '../convex/_generated/api'

const client = new ConvexClient(import.meta.env.VITE_CONVEX_URL)
const tasks = shallowRef()
const unsubscribe = client.onUpdate(api.tasks.list, {}, value => (tasks.value = value))
onScopeDispose(unsubscribe)
```

That's enough for a small client-only app. What you'd write yourself as the app grows is what these packages provide:

| | `convex/browser` | `vue-convex` | `nuxt-convex` |
| --- | --- | --- | --- |
| Reactive query state (`data`, `error`, `status`) | write it | yes | yes |
| Reactive args, `'skip'`, resubscribe only on real changes | write it | yes | yes |
| Pagination with page splitting, like `usePaginatedQuery` | write it | yes | yes |
| Pending state and errors for mutations and actions | write it | yes | yes |
| Uploads with progress, R2 uploads | write it | yes, storage | yes, plus R2 |
| Awaitable queries that run during SSR | no | yes, with your own hydration adapter | yes |
| SSR results hydrated from the payload, then live | no | adapter | built in |
| Request's user on the server, token never sent to the client | no | `serverAuth` hook | built in, Better Auth or `convex:token` |
| Server route helpers mapping errors to HTTP | no | no | yes |
| Auto-imports, `#convex/api` alias, DevTools tab | no | no | yes |

`vue-convex` follows the shape of Convex's React hooks (`useQuery`, `useMutation`, `usePaginatedQuery`) and keeps the raw clients one call away through [`vue-convex/advanced`](/api-reference/use-convex-client).

## When to pick `nuxt-convex`

- You build with Nuxt and want queries in the server HTML, live after hydration, without writing hydration code.
- You want server routes and SSR to run as the signed-in user, with Better Auth or your own provider, without exposing the token.
- You want the same composables in a plain Vue app, through `vue-convex`.

When you only need a client-side subscription or two, `convex/browser` on its own is a fine choice too.
