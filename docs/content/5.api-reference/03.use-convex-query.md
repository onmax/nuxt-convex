---
title: useConvexQuery
description: Reference for the primary read composable shared by nuxt-convex and vue-convex.
---

`useConvexQuery` subscribes to one Convex query and keeps the result up to date. Await it to wait for the first result, which is also what makes it run during SSR.

## Import

```ts [Nuxt]
// Auto-imported. Also exported from '#convex'.
const { data } = await useConvexQuery(api.tasks.list)
```

```ts [Vue]
import { useConvexQuery } from 'vue-convex'
```

## Signature

```ts
function useConvexQuery<Query extends FunctionReference<'query'>>(
  query: MaybeRefOrGetter<Query>,
  // Optional when the query takes no arguments
  args?: MaybeRefOrGetter<FunctionArgs<Query> | 'skip'>,
  options?: UseConvexQueryOptions,
): UseConvexQueryReturn<Query> & PromiseLike<UseConvexQueryReturn<Query>>

interface UseConvexQueryOptions {
  server?: boolean
  keepPreviousData?: boolean
  auth?: 'required' | 'optional' | 'none'
}

interface UseConvexQueryReturn<Query> {
  data: Readonly<Ref<FunctionReturnType<Query> | undefined>>
  error: Readonly<Ref<Error | ConvexError<Value> | null>>
  status: Readonly<Ref<'idle' | 'pending' | 'success' | 'error'>>
  isPending: ComputedRef<boolean>
  isSkipped: ComputedRef<boolean>
  suspense: () => Promise<FunctionReturnType<Query> | undefined>
}
```

## Parameters

| Parameter | Type | Meaning |
| --- | --- | --- |
| `query` | `FunctionReference<'query'>` | Generated Convex query reference, or a getter returning one |
| `args` | `FunctionArgs<Query> \| 'skip'` | Query arguments, a ref or getter of them, or `'skip'` to pause the query. Optional when the query takes none |
| `options.server` | `boolean` | Fetch during SSR when awaited. Defaults to the module's `ssr` option (the plugin's `server` option in Vue) |
| `options.keepPreviousData` | `boolean` | Keep the previous result while the query for new args loads |
| `options.auth` | `'required' \| 'optional' \| 'none'` | How the query depends on the user. Defaults to `'optional'` |

### `auth`

- `'optional'`: runs with whatever auth the client has, signed in or not.
- `'required'`: stays `idle` until the user is authenticated, then runs. It replaces `computed(() => isAuthenticated.value ? args : 'skip')`.
- `'none'`: the result doesn't depend on the user. During SSR it runs without resolving the request's token.

## Return value

| Field | Type | Meaning |
| --- | --- | --- |
| `data` | `Ref<T \| undefined>` | Latest result. `undefined` while pending, skipped, or after an error |
| `error` | `Ref<Error \| ConvexError \| null>` | Latest error. Use [`isConvexError`](/nuxt-module/error-handling) to read `ConvexError` data |
| `status` | `Ref<'idle' \| 'pending' \| 'success' \| 'error'>` | `idle` while skipped |
| `isPending` | `ComputedRef<boolean>` | `status === 'pending'` |
| `isSkipped` | `ComputedRef<boolean>` | `status === 'idle'` |
| `suspense` | `() => Promise<T \| undefined>` | Resolves with the first result and rejects on error |

## Behavior

- The return value is awaitable. `await useConvexQuery(...)` resolves with the same refs once the first result or error is in, and never rejects. Use `suspense()` when you want a rejection instead.
- On the server, awaiting fetches the query once over HTTP and records the result for hydration. Identical queries in one request share the fetch. Without `await`, nothing is fetched and the query renders as `pending`.
- On the client, a hydrated result is used for the first render, then the WebSocket subscription takes over. The client never fetches queries over HTTP.
- With a value already in the client's cache (another component subscribes to the same query and args), the query starts with it instead of `pending`.
- Changing args resets `data` to `undefined` unless `keepPreviousData` is set. Deep-equal args don't resubscribe.
- Args that Convex can't serialize, such as a `Date`, put the query in the `error` state instead of throwing.
- Before the runtime has a URL, the query stays `pending` and subscribes once a client connects.
