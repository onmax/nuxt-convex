Configure `nuxt-convex` with the `convex` key in `nuxt.config.ts`. Every option is optional: with a `CONVEX_URL` in the environment, `modules: ['nuxt-convex']` is a working setup.

`nuxt-convex` supports Nuxt `>=4.6.0 <6.0.0`.

## Example

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-convex'],
  convex: {
    url: 'https://happy-otter-123.convex.cloud',
    ssr: true,
    storage: true,
    clientOptions: {
      unsavedChangesWarning: false,
    },
    auth: {
      provider: 'better-auth',
      basePath: '/api/auth',
    },
  },
})
```

## Options

| Option | Type | Default | Meaning |
| --- | --- | --- | --- |
| `url` | `string` | from env | Convex deployment URL. See [URL resolution](#url-resolution). |
| `siteUrl` | `string` | from env, else derived | HTTP actions URL (`https://<name>.convex.site`). Used by the Better Auth proxy. |
| `dir` | `string` | `'convex'` | Convex source directory. Relative paths are resolved across Nuxt layers. |
| `ssr` | `boolean` | `true` | Default for running awaited queries during SSR. Each query can override it with its `server` option. |
| `server` | `boolean` | | Deprecated name of `ssr`. Still works and logs a deprecation warning. |
| `storage` | `boolean` | `false` | Adds `#convex/storage`, the storage auto-imports, and scaffolds `convex/_hub/storage.ts`. |
| `r2` | `boolean` | `false` | Adds the `useConvexR2Upload` auto-import. |
| `clientOptions` | `ConvexClientConfig` | `{}` | Options for the browser `ConvexClient`. See [Client options](#client-options). |
| `auth` | `boolean \| ConvexAuthConfig` | see below | Token provider for SSR and server routes, and the Better Auth proxy. See [Auth](#auth). |
| `devtools` | `boolean` | `true` | Adds a Convex tab to Nuxt DevTools in development. |

### `ssr` and `server`

The module option is `ssr`, like the top-level `ssr` in `nuxt.config.ts`: it sets the default for the whole app. The per-query option is `server`, like `useFetch(url, { server: false })`: it overrides that default for one call.

```ts
// Never runs during SSR, even with `convex.ssr: true`
const { data } = await useConvexQuery(api.tasks.list, {}, { server: false })
```

See [SSR & Hydration](/nuxt-module/ssr-and-hydration) for what each combination does.

## URL resolution

At build time, the first value found wins:

1. `convex.url` in `nuxt.config.ts`
2. `CONVEX_URL`
3. `NUXT_PUBLIC_CONVEX_URL`
4. `VITE_CONVEX_URL`
5. `.env.local`, in development only (`npx convex dev` writes it, and Nuxt doesn't load it by itself)

`siteUrl` resolves the same way from `convex.siteUrl`, `CONVEX_SITE_URL`, `NUXT_PUBLIC_CONVEX_SITE_URL`, `VITE_CONVEX_SITE_URL` and `.env.local`. When none is set it's derived from the deployment URL at runtime: `https://x.convex.cloud` becomes `https://x.convex.site`, and a local backend's port goes up by one (`3210` becomes `3211`).

At runtime, `NUXT_PUBLIC_CONVEX_URL` and `NUXT_PUBLIC_CONVEX_SITE_URL` override the built values, so one build can point at different deployments. If you override the URL at runtime and baked a `siteUrl` into the build, override the site URL too.

Without a URL, the app starts disconnected: queries stay pending, and the module warns in development.

See [Local Development](/getting-started/local-development) for the full picture of where these variables come from.

## Client options

`clientOptions` is passed to the browser `ConvexClient`. Only JSON-serializable options are accepted, because they travel through `runtimeConfig`:

| Option | Meaning |
| --- | --- |
| `verbose` | Log client activity to the console |
| `logger` | `false` silences the client's console logging |
| `unsavedChangesWarning` | Warn before closing the tab while a mutation is in flight. On by default in browsers |
| `skipConvexDeploymentUrlCheck` | Skip the client's check that the URL looks like a Convex Cloud deployment, for self-hosted backends. Also applied to the server's HTTP client |
| `authRefreshTokenLeewaySeconds` | How long before expiry the client refreshes its token |
| `expectAuth` | Hold queries until a token is set. The module turns it on by itself when SSR rendered a signed-in user |
| `reportDebugInfoToConvex` | Send client debug info to Convex |
| `initialAuthTokenReuse` | Reuse the cached token after it's confirmed instead of fetching a fresh one |

For a custom logger object, or anything that isn't serializable, configure the client yourself through [`#convex/advanced`](/api-reference/use-convex-controller).

## Auth

```ts
interface ConvexAuthConfig {
  provider?: 'better-auth' | false
  basePath?: string
  proxy?: boolean
}
```

| Option | Default | Meaning |
| --- | --- | --- |
| `provider` | `'better-auth'` when `@nuxtjs/better-auth` is installed, else `false` | Built-in token provider. `'better-auth'` exchanges the Better Auth session cookie for a Convex JWT. With `false`, tokens come only from the [`convex:token` hook](/nuxt-module/authenticated-ssr#custom-providers). |
| `basePath` | `'/api/auth'` | Better Auth base path. The token is read from `<basePath>/convex/token`. |
| `proxy` | `true` with the `better-auth` provider | Proxies `<basePath>/**` to the Convex site URL, where Better Auth runs as a Convex component. Defaults to `false` when `@nuxtjs/better-auth` runs its own server (`auth.clientOnly: false`). |

`auth: true` is the same as leaving it out. `auth: false` turns off the built-in provider, the proxy and the Better Auth client plugin; the `convex:token` hook keeps working.

With `@nuxtjs/better-auth` installed, setting its `auth.database.provider` to `'convex'` fails the build: that provider was removed. See [Better Auth](/integrations/better-auth) for the supported setup.

## What the module adds

The public Nuxt alias matrix is `#convex`, `#convex/api`, `#convex/advanced`, with optional `#convex/storage` when storage is enabled. Server code also gets `#convex/server`.

Always:

- `#convex`, `#convex/api` and `#convex/advanced`
- `#convex/server` in Nitro (server routes, middleware and plugins)
- auto-imports for `useConvexQuery`, `useConvexQueries`, `useConvexMutation`, `useConvexAction`, `useConvexPaginatedQuery`, `useConvexAuth` and `useConvexConnectionState`
- server auto-imports for `useConvexServer`, `serverConvexQuery`, `serverConvexMutation`, `serverConvexAction`, `getConvexToken`, `requireConvexAuth` and `toConvexH3Error` (Nitro 2 only, see [Server Routes](/nuxt-module/server-routes))
- the components `ConvexQuery`, `ConvexPaginatedQuery`, `ConvexAuthenticated`, `ConvexUnauthenticated` and `ConvexAuthLoading`. They're registered as Nuxt components, so they're auto-imported where you use them and left out of pages that don't
- a server middleware that resolves the request's Convex token on demand
- the Better Auth proxy route, when `auth.proxy` is on

With `storage: true`:

- `#convex/storage`
- auto-imports for `useConvexStorage` and `useConvexUpload`
- `convex/_hub/storage.ts`, scaffolded if missing

With `r2: true`:

- the `useConvexR2Upload` auto-import

The module does not create an R2-specific alias.

In development, the module also watches for `convex/_generated/` to appear (so starting `npx convex dev` after `nuxt dev` needs no restart) and, with `devtools` on, adds a DevTools tab that links to your deployment in the Convex dashboard.

## Runtime config

The resolved options are written to `runtimeConfig.public.convex`:

```ts
interface ConvexPublicRuntimeConfig {
  url: string
  siteUrl: string
  ssr: boolean
  storage: boolean
  r2: boolean
  clientOptions: ConvexClientConfig
  auth: {
    provider: 'better-auth' | 'none'
    basePath: string
    proxy: boolean
  }
}
```

Values you set yourself under `runtimeConfig.public.convex` take precedence over the module's.
